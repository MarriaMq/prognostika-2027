# Прогностика 2027: что уже сделано

Telegram mini app с нумерологическим прогнозом на 2027 год. Это готовый HTML-прототип в формате обычного приложения: экраны, кнопки, тексты. Дальше хотим попробовать другой подход: анимированное приложение, ближе к игре.

## Что лежит в архиве
- `v5/index.html` — актуальная версия (v121) в одном файле: дизайн, логика экранов, тексты RU/UA, анимации. Картинки в `v5/assets/`.
- `index.html` в корне только перенаправляет на `v5/`.
- Старые версии (v1–v120, v2–v4) с сайта удалены 26.11.2026, чтобы не путать. Они остались в истории git, любую можно восстановить.

Онлайн: https://prognostica2027.botmaker.com.ua/v5/ (старый адрес https://marriamq.github.io/prognostika-2027/v5/ перекидывает туда сам; репозиторий MarriaMq/prognostika-2027).

## Домен
Мини-апп живёт на поддомене **https://prognostica2027.botmaker.com.ua/** (DNS в Cloudflare у Марии).
- **Сейчас** поддомен смотрит на GitHub Pages прототипа: запись CNAME `prognostica2027` → `marriamq.github.io`, облако серое (DNS only). Это временный адрес, не боевой сервер.
- **Когда сервер готов**, скажи Марии IP. Она поменяет запись на A `prognostica2027` → IP сервера, а поддомен отвяжет от GitHub Pages. На сервере нужен HTTPS-сертификат (Let's Encrypt).
- **В BotFather** сразу ставь кнопку мини-аппа на этот поддомен: после переезда на сервер в настройках бота ничего менять не придётся.
- **Демо-ссылки.** В `v5/index.html` (`DEMO_OK`) поддомен разрешён для демо-ссылок `?demo=…`. На боевом сервере убрать его оттуда, иначе платный прогноз откроется по ссылке.
- **API на том же поддомене.** Если `/api/track` и остальное API будут на этом же поддомене, CSP `connect-src 'self'` менять не нужно.

## Годовая прогностика по 22 арканам (формулы от клиентки, 26.11.2026)
Прогностический год начинается со дня рождения, а не с 1 января: например, с октября 2027 по октябрь 2028. «Интересующий год» в формуле — это год, в котором период начинается.

**Приведение к аркану.** Если результат больше 22, отнимаем 22, пока не получится число от 1 до 22. Число 22 остаётся 22.

**1. Общий прогноз** (вкладка «Общий»): карьера, бизнес, финансы, самореализация. Блоки: Общий фон, Карьера и бизнес, Финансы, Самореализация, Сложный период, Что делать.
- Формула: число рождения + месяц рождения + сумма цифр интересующего года.
- Пример 28.10.1998, на 2027: 28 + 10 + 11 = 49 → 49 − 22 − 22 = **5 аркан**, период октябрь 2027 – октябрь 2028.
- На 2026: 28 + 10 + 10 = 48 → **4 аркан**, период октябрь 2026 – октябрь 2027.

**2. Личный прогноз** (вкладка «Личный»): любовь, отношения, эмоциональное состояние, брак, дети, семья. Блоки: Общий фон, Любовь и отношения, Эмоциональное состояние, Брак, дети и семья, Сложный период, Что делать.
- Формула: сумма всех цифр полной даты рождения + сумма цифр интересующего года (каждая цифра отдельно).
- Пример 28.10.1998, на 2027: 2+8+1+0+1+9+9+8 + 2+0+2+7 = 49 → **5 аркан**.
- На 2026: 2+8+1+0+1+9+9+8 + 2+0+2+6 = 48 → **4 аркан**.

**Какой период действующий.** Если день рождения в текущем году ещё не наступил, действующий прогноз считается по предыдущему году. В приложении это уже так: экран «Год» сразу открывает действующий период, второй доступен стрелкой.
- Период 2026–2027 (`YEAR_PREV`) считается с годом 2026 (сумма цифр 10).
- Период 2027–2028 (`YEAR_TEXT`) считается с годом 2027 (сумма цифр 11).

**Для программиста (JS):**
```js
const digits = n => String(n).split('').reduce((a, c) => a + +c, 0);
const toArcana = n => { while (n > 22) n -= 22; return n; };
// d, m — день и месяц рождения, y — год рождения, year — 2026 или 2027
const arcGeneral  = (d, m, year)    => toArcana(d + m + digits(year));
const arcPersonal = (d, m, y, year) => toArcana(digits(d) + digits(m) + digits(y) + digits(year));
```
Тексты на каждый из 22 арканов (общий и личный) клиентка пришлёт отдельно.

**Месяцы.** Формула месячной прогностики та же, что раньше, только вместо 2026 (сумма 10) берём 2027 (сумма 11). Отдельных месячных формул не будет.

## Тексты общего годового прогноза подключены (v121)
- Тексты из PDF клиентки разложены по файлам: `v5/texts/year/general/<ru|uk>/<female|male>/<01..22>.md`, 88 файлов. Как найти и заменить текст, описано в `v5/texts/README.md`. Проверка, что все файлы целы: `node v5/texts/check.mjs`.
- Приложение само считает аркан (`arcGeneral`) по дате рождения и году периода, берёт файл по языку и полу и показывает 4 рубрики. Номер аркана людям не показываем.
- Жирные выделения клиентки перенесены (403 места). В PDF жирный не размечен, его определяли по толщине штриха букв и сверили вторым способом, расхождений нет.
- Вкладка «Личный» пока на демо-текстах: формула `arcPersonal` готова, тексты ждём. Положить их в `v5/texts/year/personal/...` в том же формате.
- Для сервера: сейчас файлы лежат открыто. В рабочей версии отдавать их только после проверки оплаты (см. пункт 3 ниже).

## Два личных года (v111–v114)
- 2027 накрывают два личных года: от дня рождения 2026 до дня рождения 2027 и от дня рождения 2027 до 2028. На экране «Год» между ними переключают стрелки. У родившихся 1 января период один.
- Даты пишутся «с 25.08.26 по 25.08.27», месяцы «с 25.01 по 25.02»: конец подписи совпадает с началом следующего периода.
- Тексты периода 2026–2027 (`YEAR_PREV`) пока демо, их должна дать формула.

## Безопасность: что обязательно сделать на сервере (проверка 26.11.2026)
Во фронте проверено: имена, промокод и фото из Telegram выводятся только через экранирование, внешних запросов и хранилища в браузере нет, ключей и секретов в коде нет. Добавлены политика безопасности (CSP) и проверка параметров ссылки; демо-ссылки (`?demo=…&access=all`) работают только на localhost и на GitHub Pages прототипа.

Но прототип сам решает, что куплено. В рабочей версии это должно решать только сервер:
1. **Проверять `initData` на сервере** подписью бота (HMAC-SHA256 по документации Telegram) и срок `auth_date`. `initDataUnsafe` годится только для показа имени и фото, не для доступа.
2. **Доступ (`access`) брать только с сервера** по проверенному Telegram ID. Никаких флагов в URL или в браузере.
3. **Тексты прогнозов отдавать с сервера только после проверки оплаты.** Сейчас `MONTH_TEXT`, `YEAR_TEXT`, `YEAR_PREV` и папка `v5/texts/` лежат открыто и видны любому через «Просмотр кода».
4. **Оплату monoPay подтверждать вебхуком на сервере** с проверкой подписи, суммы и ID заказа. Экран «Оплата прошла» не должен открывать доступ сам по себе. Цену заказа считает сервер, а не страница.
5. **Промокоды проверять и гасить на сервере** (одноразовость, срок, кто использовал). Тестовый список `PROMO_TEST` из страницы убрать.
6. **Отдавать страницу по HTTPS** и добавить заголовки ответа: `Content-Security-Policy` с `frame-ancestors https://web.telegram.org https://*.telegram.org` (в meta это не работает), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
7. **Дописать домен API в `connect-src`** в CSP в `<head>`, иначе запросы к бэкенду заблокируются.
8. **Данные людей** (имя, дата рождения, пол, близкие) хранить только на сервере, не писать в логи целиком, удалять по запросу. Дата рождения близкого — персональные данные третьего лица.
9. По желанию: шрифты Google положить к себе на сервер, чтобы IP пользователей не уходил в Google.
